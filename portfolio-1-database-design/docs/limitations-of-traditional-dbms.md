# Limitations of a traditional relational DBMS, applied to Konga

_Study Session 1, 1.1.8 lists the limitations that led to NoSQL, NewSQL and distributed/cloud databases. This page shows where each one would affect a marketplace like Konga, and which portfolio responds to it._

The design in this portfolio is relational, and for orders, payments and stock that is the right choice. The table below is about where that choice starts to strain. Most of the responses come in later portfolios; only the security row is answered here.

| Limitation (study session)                                           | Where it appears in Konga                                                                                                                       | Response in the portfolios                                                                                           |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Scalability (vertical scaling is costly, horizontal scaling is hard) | Flash-sale traffic lands on `orders` and `inventory` at the same time                                                                           | Portfolio 5: partitioning, read replicas and a discussion of sharding                                                |
| Rigid schema                                                         | Product attributes differ per category (RAM for a phone, size for a shirt, panel type for a TV), and every new attribute means an `ALTER TABLE` | Portfolio 4: document model for product attributes                                                                   |
| Limited performance with big data                                    | Clickstream, search and review text at large volume                                                                                             | Portfolio 2: indexing. Portfolios 4 and 5: discussion of big data and cloud                                          |
| Complexity with distributed data                                     | Orders in Lagos and Abuja are served from different regions                                                                                     | Portfolio 5: fragmentation, replication and consistency                                                              |
| High maintenance cost                                                | Tuning and backups take DBA time; see the [maintenance plan](design-report.md#stage-7-deployment-and-maintenance)                               | Portfolio 5: managed cloud databases (Session 3)                                                                     |
| Concurrency and locking issues                                       | Two customers try to buy the last unit; deadlocks                                                                                               | Portfolio 3: isolation levels, row locks and a deadlock demonstration                                                |
| Limited real-time analytics (OLTP vs OLAP)                           | Sales dashboards run on the same tables as checkout and slow it down                                                                            | Portfolio 2: materialised view. Portfolio 5: warehouse or replica for analytics                                      |
| Security and compliance                                              | The database holds customers' personal data                                                                                                     | Portfolio 1: [least-privilege roles and a column-level grant](design-report.md#roles). Portfolio 5: security section |
| Inability to handle NoSQL requirements                               | Reviews, sessions, recommendations and product graphs do not fit tables well                                                                    | Portfolio 4: document, key-value and graph models                                                                    |
| Limited cloud integration                                            | Moving an on-premises PostgreSQL to a managed service                                                                                           | Portfolio 5: cloud deployment design                                                                                 |
